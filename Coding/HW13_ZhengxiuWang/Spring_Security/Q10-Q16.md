## Spring Security Interview Questions (Q10 - Q19)

### 10. How do we use session and cookie to keep user information?
- **Session** stores data on server side.
- **Cookie** stores small data in the browser.
- After login, server creates a session and gives the session ID as cookie.
- Every request includes that cookie to recognize the user.

---

### 11. What is the *Spring Security Filter*?
- A chain of filters that process HTTP requests.
- It handles things like authentication, authorization, CSRF, etc.
- Example: `UsernamePasswordAuthenticationFilter`, `BasicAuthenticationFilter`.

---

### 12. Explain *Bearer Token* and how *JWT* works.
- **Bearer token**: Token sent in header: `Authorization: Bearer <token>`.
- **JWT**: JSON Web Token has 3 parts: Header, Payload, Signature.
- Server verifies signature to check token validity.

---

### 13. How to store sensitive user data like passwords?
- Never store plain text.
- Use hashing like **BCrypt** for passwords.
- For credit card info: encrypt using **AES** or use secure vaults.

---

### 14. Compare common authentication components:
- **UserDetailsService**: Loads user data from DB.
- **AuthenticationProvider**: Validates user login.
- **AuthenticationManager**: Delegates to provider(s).
- **AuthenticationFilter**: Intercepts HTTP requests to start login.

---

### 15. What is the disadvantage of Session?
- Not stateless; server must store session data.
- Hard to scale across servers.
- Solution: Use **JWT** or **Redis-backed session**.
