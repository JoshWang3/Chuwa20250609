# Spring Security – Q1 & Q2

## ✅ 1. Annotations Learned

| Annotation | Meaning |
|------------|---------|
| `@EnableWebSecurity` | Enables Spring Security for web apps. |
| `@Configuration` | Marks the class as a config class. |
| `@Bean` | Registers a method return as a Spring bean. |
| `@PreAuthorize("hasRole('ROLE_XXX')")` | Checks role before running the method. |
| `@PostAuthorize(...)` | Checks role after method runs. |
| `@Secured("ROLE_ADMIN")` | Also for method-level security. |
| `@WithMockUser` | Used in tests to fake a logged-in user. |
| `@RestController` | Creates a REST API controller. |
| `@CrossOrigin` | Allows CORS (cross-origin) requests. |

## ✅ 2. Security Concepts

### TLS
A secure protocol that encrypts data between client and server. It keeps data safe, private, and trusted.

### PKI
Public Key Infrastructure. A system to manage trusted certificates using public/private keys and certificate authorities (CAs).

### Certificate
A digital file that shows a site’s identity. It includes:
- The site’s name
- Its public key
- A signature from a trusted CA

### Public Key & Private Key
- **Public Key**: Shared with everyone, used to encrypt or verify.
- **Private Key**: Kept secret, used to decrypt or sign data.

Only someone with the private key can create a valid signature that the public key can check.

### Signature
- A private key signs the data hash.
- The public key checks if the signature is valid.
- This proves the data is real and not changed.

### Summary

| Concept | What it does |
|--------|---------------|
| TLS | Encrypts communication |
| PKI | Manages trusted keys/certs |
| Certificate | Proves site identity |
| Public Key | Used to verify or encrypt |
| Private Key | Used to sign or decrypt |
| Signature | Proves data is real |
