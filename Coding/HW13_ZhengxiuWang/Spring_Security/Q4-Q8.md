## ✅ Q4. HTTP Status Codes for Authentication & Authorization Failures

| Status Code | Meaning | When It Happens |
|-------------|---------|-----------------|
| 401 Unauthorized | User is **not logged in** or token is missing/invalid | Authentication failed |
| 403 Forbidden | User is logged in but has **no permission** to access the resource | Authorization failed |
| 400 Bad Request | Often caused by malformed credentials or missing parameters | Invalid login request |
| 302 Found | Redirect to login page in session-based auth | Browser redirect before login |

## ✅ Q5. Compare Authentication vs Authorization (with Spring Security)

| Concept | Authentication | Authorization |
|--------|------------------|----------------|
| Meaning | Verify **who** the user is | Verify **what** the user can do |
| Happens First? | ✅ Yes | After authentication |
| Spring Component | `UsernamePasswordAuthenticationFilter` | `AccessDecisionManager`, `@PreAuthorize`, `@Secured` |
| Example | Login with username/password | Access control like `hasRole("ADMIN")` |

**Authentication Components in Spring:**
- `AuthenticationManager`: Handles login logic
- `UserDetailsService`: Loads user info from DB
- `SecurityContextHolder`: Stores authenticated user

**Authorization Components in Spring:**
- `@PreAuthorize`, `@Secured`: Method-level access control
- `AccessDecisionVoter`: Determines if access is allowed
- `HttpSecurity.authorizeRequests()`: URL-level access rules

## ✅ Q6. Explain HTTP Session

- A session stores user data **on the server side** after login.
- Each session is identified by a unique session ID stored in a cookie.
- Useful to keep the user logged in across multiple pages.

**Example:**
- User logs in → session ID is created → stored in browser → used in future requests

---

## ✅ Q7. Explain Cookie

- A cookie is a **key-value pair stored on the client (browser)**.
- It’s automatically sent with every request to the server.
- Can be used to store:
    - Session ID
    - Preferences (language, theme)
    - Authentication tokens (e.g. JWT)

---

## ✅ Q8. Compare Session and Cookie

| Feature | Session | Cookie |
|---------|--------|--------|
| Storage | Server side | Client side (browser) |
| Size Limit | Large (server memory) | Small (~4KB) |
| Security | More secure | Less secure, can be stolen |
| Common Use | Login state, shopping cart | Remember username, dark mode |

**Conclusion:**
- Session is more secure and used to store sensitive data.
- Cookies are lighter and often used to identify or track users.
