  13. What is ThreadPool? How many types of ThreadPool? What is the TaskQueue in ThreadPool?
        ThreadPool use pre-initialized reusable threads to execute tasks efficiently.
        a.FixedThreadPool: fixed number of threads and thread count never changes (Executors.newFixedThreadPool(5);)
        b.CachedThreadPool: created new threads as needed (Executors.newCachedThreadPool();)
        c.SingleThreadExecutor: thread pool with only one thread
        d.ScheduledThreadPool: thread pool that supports scheduled and periodic tasks
        e.WorkStealingPool: thread pool based on work-stealing algorithm
        TaskQueue is the queue that stores pending tasks in a thread pool. They are waiting to be executed when
        core threads become available.

  18. What is Atomic classes? How many types of Atomic classes? Give me some code example of Atomic classes and
  its main methods. when to use it?
        Atomic classes provide lock-free thread-safe operations. We use atomic class for easy operations (like counters,
        flags), high concurrency scenarios, replace synchronized for basic operations.

        a. Atomic primitives (e.g., AtomicInteger, AtomicBoolean, AtomicLong)
        b. Atomic arrays (e.g., AtomicIntegerArray, AtomicLongArray, AtomicReferenceArray)
        c. Atomic references (e.g., AtomicReference, AtomicStampedReference, AtomicMarkableReference)
        d. Field Updaters (e.g., AtomicIntegerFieldUpdater, AtomicLongFieldUpdater, AtomicReferenceFieldUpdater)

        code example:
                a. (AtomicInteger)
                              AtomicInteger counter = new AtomicInteger(0);
                              counter.get();
                              counter.set(100);
                              counter.incrementAndGet();
                              counter.getAndSet(50) //设置新值并返回旧值
                b. (AtomicBoolean)
                              AtomicBoolean flag = new AtomicBoolean(false);
                              flag.get();
                              flag.set(true);
                              flag.compareAndSet(false, true); //如果是false就改成true
                c. (AtomicReference)
                              AtomicReference<String> ref = new AtomicReference<>("Hi");
                              ref.get();
                              ref.compareAndSet("Hi", "Hello");

                Scenario for init singleton:
                              public class Singleton{

                                    private static Singleton instance;

                                            if (flag.compareAndSet(false, true)){

                                                    System.out.println("finish init");

                                    }
                              }

  20. What kind of locks do you know? What is the advantage of each lock?

        ReentrantLock: supports fair/unfair locking, can be interrupted, more flexible control

  21. What is future and completableFuture? List some main methods of CompletableFuture.
        Future holds the result of an asynchronous operation but blocks when you call get().
        CompletableFuture is an advanced version that supports non-blocking callbacks and chaining.
        Common CompletableFuture methods include:
                CompletableFuture.supplyAsync(() -> "result");  – start a task asynchronously with a return value
                CompletableFuture.runAsync(() -> System.out.println("task")); – start a task asynchronously w/o a return value
                .thenApply(result -> result.toUpperCase());    – transform the result
                .thenAccept(result -> System.out.println(result));  – consume the result
                .thenRun(() -> System.out.println("finished"));  – run code after completion, without using the result
                .thenCombine(future2, (r1, r2) -> r1 + r2) – combine two futures' results
                .thenCompose(result -> CompletableFuture.supplyAsync(() -> result + "!")); – chain another async task
                .whenComplete((result, ex) -> System.out.println("Task done"))  – run after task finishes, whether success/failure
                .exceptionally(ex -> "default value");  – handle exceptions gracefully
                .join() – get result (blocking)
                .get() – get result (blocking, throws checked exceptions)
