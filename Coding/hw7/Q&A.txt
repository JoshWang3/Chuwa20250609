1. Explain the concept of API (Application Programming Interface), why do we need APIs.
    API is a set of rules and protocols that defines how different software applications can communicate
    and exchange data with each other.
    We need APIs because they allow applications to:
       - Access external services (payment, maps, databases)
       - Enable frontend-backend communication
       - Create reusable, modular code



2. Compare developer API vs application API (normal APIs)
    -Developer APIs that developers use within their code to access functionality.
     Developer API: methods, jar, commandline application

    -Application APIs that allow different applications to communicate over networks.
     Application API: REST API(HTTP-based), GRAPHQL, GRPC, WEBSOCKET, MQTT, MCP, SOAP



3. Name some different types of APIs
    By Protocol/Architecture Style:
             REST –  (most common, HTTP-based)
             GraphQL - (flexible queries)
             gRPC – （high-performance, binary communication protocol developed by Google）
             SOAP – An older XML-based protocol for structured messaging
             RPC – remote call style
    By Data Format:
            JSON APIs – most modern
            XML APIs – used in older systems or with SOAP
    By Access Scope:
            Public APIs – Open to external developers (e.g., Twitter API)
            Private APIs – Used internally within an organization
            Partner APIs – Shared with specific business partners
    By Use Case:
            Web APIs – used online, RESTful.
            Database APIs – Used to interact with databases (e.g., JDBC, ODBC).
            Browser APIs – Built into web browsers (e.g., DOM API, Fetch API).
            WebSocket APIs – Enable persistent, two-way communication between client and server.



4. Compare path variables vs request parameters in REST API.
    -path variables: identify a specific resource, it is the part of the URL path (/resource/{id})
    -request parameters: filter/sort/refine the resource, it is after ? in the URL (?key=value&key2=value2)

8. List HTTP methods and their meanings, and their expected HTTP status codes.
    get - Retrieve data from server
            200 OK (success)
            404 Not Found (resource doesn't exist)
            401 Unauthorized (authentication required)
    post - Create new resource
            201 Created (resource created successfully)
            400 Bad Request (invalid data)
            409 Conflict (resource already exists)
    put - Update/replace entire resource
            200 OK (updated successfully)
            201 Created (resource created if didn't exist)
            400 Bad Request (invalid data)
    patch - Partially update resource
            200 OK (updated successfully)
            400 Bad Request (invalid data)
            404 Not Found (resource doesn't exist)
    delete - Remove resource
            200 OK (deleted with response body)
            204 No Content (deleted without response body)
            404 Not Found (resource doesn't exist)
    HEAD - Get headers only
            200 OK
            404 Not Found
    OPTIONS - Get allowed methods for resource
            200 OK
    Common across all methods: 500 Internal Server Error, 401 Unauthorized, 403 Forbidden



9. Explain why REST API is stateless.
    Because each request must contain all necessary information for the server to process it, with
    the server not storing any client context between requests, which improves scalability and reliability.
    insights：
       有状态(Stateful)：
       服务器记住之前的请求信息
       服务器存储用户会话数据
       请求之间有依赖关系

       无状态(Stateless)：
       服务器不记住之前的请求
       每个请求都是独立的
       必须包含所有必要信息



10. Discuss about best practices for REST API design, from performance perspective.
    -use Pagination for Large Data Sets (which limit response size)
    -use HTTP Caching (Add cache headers like ETag, Last-Modified, and Cache-Control)
    -Field Selection (let clients request only fields they need like fields=name,email，reducing response size)
    -Compression (by gzip)
    -Asynchronous Processing for Heavy Tasks (Avoid timeouts and client blocking; return 202 Accepted)
    -Batch Requests When Possible (allow clients to send multiple operations in one request to reduce round-trips)



11. Explain the concept of XSS (Cross-Site Scripting) and CSRF (Cross Site Request Forgery) and how to
    avoid them.
    -XSS (Cross-Site Scripting) allows attackers to inject malicious scripts into websites that
     execute in other users' browsers, potentially stealing cookies or sensitive data.
     Prevented by input validation, output encoding, and Content Security Policy.
    -CSRF (Cross-Site Request Forgery) tricks users into performing unintended actions on websites
     where they're authenticated by exploiting automatic cookie submission.
     Prevented by CSRF tokens, referer validation, and SameSite cookies.

        | `Content-Type`                        | Specifies the format of the response (`application/json`).

        | `Content-Security-Policy`             | Controls what resources the browser can load, reducing XSS and injection risk.
        | `Strict-Transport-Security`           | Forces browsers to only use HTTPS for future requests.
        | `X-Rate-Limit-Limit`                  | Total number of requests allowed in a time window.
        | `X-Rate-Limit-Remaining`              | Number of remaining requests in the current window.
        | `X-Rate-Limit-Reset`                  | Time at which the rate limit resets (usually in UNIX timestamp).
