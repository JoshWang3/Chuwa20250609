//Java defines thread states in the Thread.State enum. There are 6 main states:

//NEW:	Thread is created but start() not yet called
//RUNNABLE:	Thread is ready and waiting for CPU time (includes "running")
//BLOCKED:	Thread is waiting to acquire a monitor lock (e.g. locked by another thread)
//WAITING:	Thread is waiting indefinitely for another thread to perform a specific action (wait(), join() without timeout)
//TIMED_WAITING:	Thread is waiting for a specified time (sleep(), join(timeout), wait(timeout))
//TERMINATED:	Thread has completed execution (either normally or via exception)

question 13:
1. A ThreadPool is a pool (group) of reusable threads for executing tasks.
Instead of creating a new thread for each task, Java reuses a limited number of threads from a pool, improving performance, resource usage, and scalability.
Java provides thread pools via the ExecutorService interface and Executors utility class.
2.Benefits of Using ThreadPool
Avoids thread creation overhead
Controls concurrency level
Allows task queuing and scheduling
Prevents resource exhaustion in high-load environments

3. Types of ThreadPool
1. Executors.newFixedThreadPool(int n)
Pool with a fixed number of threads
Extra tasks are queued
2. Executors.newCachedThreadPool()
3. Executors.newSingleThreadExecutor()
4. Executors.newScheduledThreadPool(int n)

The TaskQueue is an internal blocking queue used to store submitted tasks waiting to be executed.
It allows:
Task buffering (when all threads are busy)

Controlled execution rate
Java’s default implementation:
Usually LinkedBlockingQueue<Runnable> in ThreadPoolExecutor.

question 19： Concurrent collections are Java-provided data structures that allow safe access and modification by multiple threads without external synchronization.

They use advanced techniques like lock striping, CAS (Compare-And-Swap), or non-blocking algorithms to maximize performance.
ConcurrentHashMap<K, V>	Map	Thread-safe, high-performance hash map
ConcurrentLinkedQueue<E>	Queue	Non-blocking, FIFO queue
ConcurrentLinkedDeque<E>	Deque	Double-ended version of the above
CopyOnWriteArrayList<E>	List	Thread-safe list using copy-on-write
CopyOnWriteArraySet<E>	Set	Set backed by CopyOnWriteArrayList
BlockingQueue<E> (interface)	Queue	For producer-consumer; includes ArrayBlockingQueue, LinkedBlockingQueue, etc.
ConcurrentSkipListMap<K,V>	SortedMap	Thread-safe sorted map (like TreeMap)
ConcurrentSkipListSet<E>	SortedSet	Thread-safe sorted set (like TreeSet)
DelayQueue<E>	Queue	Tasks that become available after a delay
SynchronousQueue<E>	Queue	No internal storage; one-to-one handoff

question20：
1. synchronized Lock (Intrinsic Lock / Monitor Lock)
Simple and easy to use

Automatically released (no need to unlock explicitly)

Works well for basic synchronization

2. ReentrantLock (Explicit Lock)
Reentrant: A thread can acquire the lock multiple times

Fine-grained control: supports tryLock(), lockInterruptibly(), fair mode

Supports multiple Condition objects for more advanced wait/notify patterns

3. ReadWriteLock
Improves concurrency when reads are frequent
Write lock blocks all, but multiple reads can happen simultaneously

4. StampedLock
Optimistic read allows fast non-blocking reads if no write is occurring
Better performance in high-read-low-write environments

5. Object.wait() / notify() / notifyAll()
Lightweight and simple for condition waiting
Can be used for classic producer-consumer problems
