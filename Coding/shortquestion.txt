The concept of api:
An API is a set of rules and protocols that allows one software application to interact with another.
APIs are essential because they:

1. Enable communication between systems

2. Promote reusability

3. Encapsulate complexity

4. Enable scalability and modularity

5. Support third-party integration

 Path variables identify a resource, while request parameters filter or modify how the resource is returned.

question5:
1. HTTP Method :	Defines the type of operation	GET, POST, PUT, DELETE, PATCH	Specifies whether you're reading, creating, updating, or deleting a resource
2. URI (Uniform Resource Identifier):	Identifies the resource path	/api/users/123	Indicates which resource you're operating on
3. Path Variables:	Dynamic parts of the URI	/users/{id} → /users/123	Used to access a specific instance of a resource
4. Query Parameters:	Optional filters/configs in the URL	/users?page=1&sort=name	Used to filter, sort, or paginate a resource collection
5. Request Headers:	Metadata sent with the request	Authorization: Bearer token, Content-Type: application/json	Used for authentication, content negotiation, caching, etc.
6. Request Body:	Data sent with POST, PUT, or PATCH requests	{ "name": "Alice" }	Carries the actual data to be stored or updated
7. Response Status: Code	Indicates the outcome of the request	200 OK, 201 Created, 404 Not Found	Tells the client whether the request was successful or not
8. Response Headers:	Metadata in the response	Content-Type: application/json, Cache-Control	Provides additional info about the response
9. Response Body: Data returned from the server	{ "id": 123, "name": "Alice" }	Contains the actual requested data or confirmation message

question 9:
A stateless REST API means that each request from the client must contain all the information the server needs to fulfill that request.
The server does not store any context or session state about the client between requests.

XSS injects malicious code into trusted content (user → other users), while CSRF tricks a trusted user into sending unwanted requests (user → server). 
Prevent both with proper input handling, token-based security, and cookie protection.
