### 1. Explain and compare following concepts, provide specific examples when doing comparison:
1.1 Testing Related Concepts
- Unit Testing
  - Definition: Testing individual components or functions in isolation.
  - Example: Testing a Java method that calculates discounts without involving the database.

- Functional Testing
  - Definition: Validates specific functionalities of the system based on requirements.
  - Example: Testing if a login form correctly authenticates users.

- Integration Testing
  - Definition: Testing interactions between integrated modules or services.
  - Example: Testing API calls between frontend and backend.

- Regression Testing
  - Definition: Ensures existing functionalities are unaffected after code changes.
  - Example: Running test cases after adding a new feature to check old features still work.

- Smoke Testing
  - Definition: Quick check of basic functionalities after a build/deployment.
  - Example: Verifying that main pages load correctly after deployment.

- Performance Testing
  - Definition: Measures system responsiveness and stability under workload.
  - Example: Testing API response times under 1000 concurrent users.

- Stress Testing
  - Definition: Determines system behavior under extreme conditions.
  - Example: Sending 10,000 simultaneous requests to check system stability.

- A/B Testing
  - Definition: Compares two versions of a feature to determine which performs better.
  - Example: Comparing two versions of a webpage to see which generates more clicks.

- End-to-End Testing
  - Definition: Tests the complete workflow from start to finish.
  - Example: Placing an order from login to payment confirmation in an e-commerce site.
  
- User Acceptance Testing (UAT)
  - Definition: Testing by end-users to validate the system meets their needs.
  - Example: Business users testing a new CRM feature before go-live.

1.2 Environment Related Concepts
- Development Environment
  - Definition: Where developers build and test their code locally or in isolated environments.
  - Purpose: Frequent code changes, debugging, initial unit testing.
  
- QA (Quality Assurance) Environment
  - Definition: Controlled environment for executing functional, regression, and integration tests.
  - Purpose: Ensures code quality before further promotion.

- Pre-prod / Staging Environment
  - Definition: Mirrors production environment closely for final validations.
  - Purpose: Perform end-to-end, UAT, and smoke testing before production release.

- Production Environment
  - Definition: Live environment where real users interact with the application.
  - Purpose: Actual service delivery to customers.
