### 1. Explain monolithic architecture, service oriented architecture and Micro service architecture.
- Monolithic Architecture
  - All components are part of a single application.
  - Tight coupling.
  - Deployment as one unit.
  - Example: Traditional web applications.

- Service-Oriented Architecture (SOA)
  - Application broken into reusable services.
  - Typically, uses an Enterprise Service Bus (ESB) for communication.
  - Shared resources between services.

- Microservice Architecture
  - Small, independent services focused on specific functionalities.
  - Communicate via lightweight protocols (HTTP/REST, messaging).
  - Independent deployment and scaling.
  - Example: Netflix, Amazon backend.

### 2. Document the microservice architecture and core components
- API Gateway: Entry point for clients.
- Service Registry & Discovery: Keeps track of services (e.g., Eureka).
- Config Server: Centralized externalized configuration.
- Circuit Breaker: Prevent cascading failures.
- Load Balancer: Distributes requests across services.
- Monitoring & Tracing: Health checks, logs, distributed tracing.
- Security: Centralized authentication/authorization.

### 3. Explain Resilience patterns? Explain circuit breaker with Spring Cloud Hystrix code example.
3.1 Resilience Patterns
- Retry: Retry failed requests automatically.
- Timeout: Define max waiting time for a response.
- Circuit Breaker: Stops calls to a failing service temporarily.
- Bulkhead: Isolate failures in different parts of the system.

3.2 Circuit Breaker
- The Circuit Breaker is a resilience pattern that prevents a system from repeatedly trying to call a failing service. It helps avoid overloading the service and allows it time to recover.
- Sample code
```java
import com.netflix.hystrix.contrib.javanica.annotation.HystrixCommand;

@Service
public class MyService {

    @HystrixCommand(fallbackMethod = "fallbackMethod")
    public String callRemoteService() {
        // Code that may fail
        return restTemplate.getForObject("http://REMOTE-SERVICE/endpoint", String.class);
    }

    public String fallbackMethod() {
        return "Fallback response: Service is currently unavailable.";
    }
}

```

### 4. Explain load balancing algorithms.
4.1 What is balancing algorithms.
- Load balancing algorithms decide how to distribute incoming traffic across multiple service instances or servers. The goal is to optimize resource use, prevent overload, and ensure high availability.
4.2 Common Load Balancing Algorithms.

  | Algorithm                | How It Works                                                                     |
  |--------------------------|----------------------------------------------------------------------------------|
  | **Round Robin**          | Sends requests to each server in a circular order (1 → 2 → 3 → 1...).            |
  | **Random**               | Selects a server randomly for each request.                                      |
  | **Least Connections**    | Sends traffic to the server with the fewest active connections.                  |
  | **Weighted Round Robin** | Like Round Robin, but gives more traffic to servers with higher weight.          |
  | **IP Hash**              | Uses the client's IP address hash to pick a server — ensures session stickiness. |

### 5. Explain API Gateway.
5.1 What is API Gateway.
- An API Gateway is a single entry point for all client requests in a microservices architecture.
5.2 Responsibilities of an API Gateway
- | Function                      | Description                                              |
  |-------------------------------|----------------------------------------------------------|
  | **Routing**                   | Forwards requests to the correct backend service.        |
  | **Authentication & Security** | Verifies tokens (e.g., JWT), blocks unauthorized access. |
  | **Load Balancing**            | Distributes requests across multiple instances.          |
  | **Rate Limiting**             | Prevents overuse by limiting request rates per client.   |
  | **Caching**                   | Stores common responses to reduce backend load.          |
  | **Logging & Monitoring**      | Logs requests, errors, and metrics for observability.    |
  | **Protocol Translation**      | Converts HTTP to WebSocket, gRPC, etc. if needed.        |

### 6. Explain service discovery and service registry
6.1 What is service discovery?
- It means automatically finding the location (IP + port) of a microservice when it's needed.
6.2 What is service registry?
- A database (or system) where all services register themselves, so others can find them.
6.3 How they work together step by step?
- Service A starts (e.g., user-service)
- It registers itself to the Service Registry (e.g., Eureka)
- Another service (e.g., order-service) needs to call user-service
- It asks the Service Registry: "Hey, where is user-service?"
- The registry returns the current address, and order-service makes the call.
