1. Requirements

   1.1 Functional Requirements

   * Users can post comments to a “room” (live stream, event, match, article)
   * Connected clients see new comments in real time
   * When a user joins, load the latest N comments
   * User Managemet: Per-user mutes, room bans, rate limits

   1.2 Non-Functional Requirements

   * Low latency: P50 < 150 ms, P99 < 500 ms 
   * High fan-out “hot” rooms with 100k+ concurrent watchers.
   * High write throughput
   * Availability > 99.9%
   * Scalability: scale to millions of concurrent WebSocket connections.
   * Security/abuse controls

2. Back-of-the-envelope estimates

   Assumptions:

   * Peak 10k comments/sec globally.
   * “Hot” room: up to 10k concurrent clients.
   * Average comment payload: 100B.
   * Persistence TTL: 30 days.

   Resources need:

   * Ingress: 10k/s*100B=1MB/s
   * Storage: 1MB*86400=86GB/day
   * Concurrent connection: ~100k

3. API design

   Http :
   * write: POST /v1/rooms/{roomId}/comments
   Body: { text, clientTs }
   Returns: { commentId, serverTs, seq }

   * delete: DELETE /v1/rooms/{roomId}/comments/{commentId}

   * read history comments: GET /v1/rooms/{roomId}/comments?limit=200&beforeSeq=…

   Websocket for real time:

   * CONNECT wss://…/realtime?token=…
   * SUBSCRIBE { roomId, fromSeq? }

   Server pushes events in Websocket:

   * CommentCreated { roomId, commentId, seq, user, text, ts, flags }
   * CommentDeleted { roomId, commentId, ts }
   * RoomControl { roomId, command }
4. Data model
    Comment: commentId (snowflake), roomId, userId, text, ts, seq (per-room), status (active/hidden/deleted), flags (spam, modHeld), reactionsCount.
    Room: roomId, settings (slowModeInterval, chatMode), counters, hotness.
    UserRoomState: block/mute lists, roles (viewer/mod).

5. Architecture
   Authentication/Account server

   Ingestion service
   * Validates, rate-limits, profanity check (fast path), emits to Pub/Sub.

   Pub/Sub 
   * Use Kafka. Partition by roomId (hot rooms get dedicated partitions).

   Fan-out (Realtime Delivery)
   * "Room workers" consume from Kafka, maintain per-room in-memory ring buffers, and push via WS to subscribers.
   
   Moderation
   * ML spam/scam models, rules; can “hold” or “delete” retroactively; emits control events.

   Persistence
   * Kafka consumers write to Cassandra/DynamoDB (TTL), and optionally compact to S3.
   Moderation

   Observability
   * Logs/metrics/traces; abuse dashboards; replay tooling from Kafka.
