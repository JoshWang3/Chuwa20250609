   The first modification is to create department table before student table. Similarly, department table has a foreign key reference to school table, and school table has no foreign key

   Since only two school ids appears in department data, so I added two schools into school table.
   student_id is declared as primary key for student table. Sql does not allow duplicate primary key, the next fix is to give a different student_id to all student records.
   Another two problems are when inserting into student and department tables, the number of columns in value does not match the number of columns in respective tables, sql throws error Column count does not match value count.
   Also I cannot delete department when there's student record whose department_id equals the id that query was to delete.

1. Did you create the table posts, if not who did it for you? Can I change this behavior? 
   I did not create the post table. I only manually created the redbook schema. 
   posts table was created by hibernate ddl auto with the code 
   '''java
    spring.jpa.hibernate.ddl-auto=update
   '''
    This line controls how Hibernate automatically handles the database schema based on JPA entity(annotated by @Entity) classes.
    One can change the behavior by setting values for spring.jpa.hibernate.ddl-auto. Some common values are
   | Value         | Description                                                                                                                |
   | ------------- | -------------------------------------------------------------------------------------------------------------------------- |
   | `none`        | 🔒 Do nothing (default if not set in Hibernate directly). Schema must be managed manually.                                 |
   | `validate`    | ✅ Validate that the schema matches the entity mappings, but **do not change it**. Throws an error if mismatches are found. |
   | `update`      | 🔁 Automatically **add or modify tables/columns** to match the entity model, **without dropping data**. Useful for dev.    |
   | `create`      | 🛠️ Drop and **recreate** the schema every time the application starts. All data is **lost**.                              |
   | `create-drop` | 🔄 Same as `create`, but **also drops the schema** when the session factory shuts down.                                    |
   | `schema`      | (Less common) Read a named schema; not typically used directly in this property.
