     * JPQL
     * use Entity name other than database table name.
     * index Parameters
     * @return post
     */
    @Query("select p from Post p where p.id = ?1 or p.title = ?2")
    Post getPostByIDOrTitleWithJPQLIndexParameters(Long id, String title);

    /**
     * JPQL
     * use Entity name other than database table name.
     * index Parameters
     * @return post
     */
    @Query("select p from Post p where p.id = :key or p.title = :title")
    Post getPostByIDOrTitleWithJPQLNamedParameters(@Param("key") Long id,
                                                   @Param("title") String title);

    /**
     * SQL
     * use database table name.
     * index Parameters
     * @return post
     */
    @Query(value = "select * from posts p where p.id = ?1 or p.title = ?2", nativeQuery = true)
    Post getPostByIDOrTitleWithSQLIndexParameters(Long id, String title);

    /**
     * SQL
     * use database table name.
     * named Parameters
     * @return post
     */
    @Query(value = "select * from posts p where p.id = :key or p.title = :title", nativeQuery = true)

Part 3: Core Conceptual Understanding

5. Technology Comparision
    1. Spring Data JPA: Provides an abstraction over JPA for easier database interaction. It simplifies CRUD operations using repositories, supports JPQL and native quaries and integrates seamleassly with Spring Boot
        Relationship: Uses Hibernate under the hood

    2. Hibernate: A JPA implementation that provides ORM(Object-Relational Mapping). It manages entities and their relationships and supports caching and lazy/eager fetching
        Relationship: Hibernate is a JPA provider used by Spring Data JPA

    3. HikariCP: A high-performance JDBC connection pool. It is fast, lightweight and optimized for low-latency applications.
        Relationship: It is used by Spring Boot to optimize database connections

    4. JDBC: A low-level API for direct database interaction. It exeutes SQL queries directly and requires manual connection management
        Relationship: Hibernate and Spring Data JPA rely on JDBC for database communication
   
6. JPA Relationships
    Annotations and Examples:
    1. @OnetoMany : Represents a one-to-many relationship
        mappedBy: Specifies the owning side of the relationship.
        cascade: Propagates operations (e.g., persist, merge) to related entities.
        fetch: Determines how data is loaded (lazy or eager).
```java
@OneToMany(mappedBy ="department", cascade = CascadeType.ALL, fetch = FeychType.LAZY)
private List<Employee> employees;
```
    2. @ManyToOne: represents a many-to-one relationship
```java
@ManyToOne(fetch = FetchType.EAGER)
@JoinColumn(name = "department_id")
private Department department;
```
    3. @MantToMany: represents a many-to-many relationship
   
```java
@ManyToMany(cascade = CascadeType.All, fetch = FetchType.LAZY)
@JoinTable(name = "student_course", 
            joinColumns = @JoinColumn(name = "student_id"),
            inverseJoinColumns = @JoinColumn(name = "course_id"))
private List<Course> courses;

```

7. Cascade Opyions in JPA
    `CascadeType.ALL`: Applies all cascade operations(PERSIST, MERGE, REMOVE, DETACH, REFRESH)
    `orphanRemoval = true`: Deletes entities that are no longer referenced
    1. PERSIST: Saves related entities when the parent is saved
    2. MERGE: updates related entities when the parent is updated
    3. REMOVE: deletes related entities when the parent is deleted
    4. DETACH: detached related entities from the persistence context
    5. REFRESH: reloads related entities from the database

8. Fetch Types in JPA
   `FetchType.LAZY`: loads data only when accessed. Use for large collections or infrequentlu accessed data
   `FetchType.EAGER`: Loads data immediately. Use for small collections or frequently accessed data

Part 4: Querying and Data Access

9. JPQL Overview:
    Java Persistence Query Language (JPQL) is an Object-oriented query language.
    Difference from SQL:JPQL queries, while SQL queries tables. JPQL uses entity attributes, while SQL uses column names.

```java
@Query("SELECT e FROM Emplouee e WHERE e.departement.name = :deptName")
List<Employee> findByDepartmentName(@Param("deptName") String deptName);
```

10. Using the @Query Annotation
    Allow custom queries in Spring Data JPA repositories

```java
//JPQL
@Query("SELECT e From Employee e WHERE e.salary > :salary")
List<Employee> findEmployeesWithSalaryGreaterThan(@Param("salary") double salary);

//Native SQL
@Query(value = "SELECT * FROM Employees WHERE salary > :salary", nativeQuery = true)
List<Employee> findEmployeesWithSalaryGreaterThan(@Param("salary") double salary);

```

Part 5: Hibernate and Entity Management

11. EntityManager vs SessionFactory
    EntityManager: JPA-specific interface for managing entities. It provides methods like `persist`, `merge` and `remove`.
    SessionFactory: Hibernate-specific interface for creating sessions. It is used for advanced Hibernate features
```java
EntityManager em = entityManagerFactory.createEntityManager();
Session session = sessionFactory.openSession();

```

12.  SessionFactory vs Session
    SessionFactory: creates `session` objects. Thread-safe and shared across the application
    Session: Represents a single unit of work. Not thread-safe; used per transaction.


Part 6 Database Fundamentals

13. SQL Transactions: A transaction is a unit of work that ensures data consistency.
    Spring/Hibernate Management: Spring uses @Transactional to manage transactions. Hibernate manages transactions via the `Session` object

14. Hibernate Caching
    First-Level Cache: 
        Scope: Session-level
        Purpose: Stores entities within the same session
    Second-Level Cache:
        Scope: Application-level (shared across sessions)
        Purpose: Stores entities for reuse across sessions.
