<h3> 7. Cascade Options in JPA </h3>
<h4> Explain cascade = CascadeType.ALL and orphanRemoval = true.
   Also describe all other CascadeType values: </h4>

<p> CascadeType.PERSIST Owning entity saved ⇒ related entity saved (save a new entity) </p>
<p> CascadeType.MERGE Owning entity merged ⇒ related entity merged (update an entity) </p>
<p> CascadeType.REMOVE Owning entity removed ⇒ related entity removed (delete an entity) </p>
<p> CascadeType.DETACH Owning entity manually detached ⇒ related entity detached (detach an entity from the persistence context) </p>
<p> CascadeType.REFRESH Owning entity refreshed ⇒ related entity refreshed (reload entity state from the database) </p>
<p> CascadeType.ALL: includes all above operations </p>
<p> orphanRemoval = true: remove entities that are no longer referenced by any other entities </p>

<h3> 8. Fetch Types in JPA </h3>
<h4> Explain FetchType.LAZY and FetchType.EAGER, and describe when to use each. </h4>
<p> FetchType.LAZY: If we don't need data from another table, JPA doesn't fetch it. </p>
<p> FetchType.EAGER: When we fetch one table, it fetches related data from another table at the same time. </p>

<h2> Part 4: Querying and Data Access </h2>
<h3> 9. JPQL Overview </h3>
<h4> Explain what JPQL is and how it differs from SQL. Include examples </h4>
JPQL is Java Persistence Query Language defined in JPA specification. 
It is used to create queries against entities to store in a relational database.
```
@Query("select p from Post p where p.title = :title")
Post getPostByTitleWithJPQLNamedParameters(@Param("title") String title);
```

SQL needs to follow the sql syntax.
```
@Query(value = "select * from posts p where p.title = :title", nativeQuery = true)
Post getPostByTitleWithSQLNamedParameters(@Param("title") String title);
```

<h3> 14. Hibernate Caching </h3>
<h4> Explain Hibernate’s caching mechanisms. Compare: First-Level Cache (session scope) Second-Level Cache (shared/global scope) </h4>
<p> First-Level Cache: Hibernate first-level is associated with a Hibernate session, entity instances stored in a 
session can be considered as "cached" inside session object. It's enabled by default. Session provides methods
through which we can persist, merge, remove, and find entity instances inside the "cache" (session) </p>
<p> Second-Level Cache: It works across sessions, in sessionFactory level. It's not enabled unless configured 
explicitly. It relies on third party caching providers such as Redis, etc. </p>
