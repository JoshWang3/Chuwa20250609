<h3>Question 5: </h3>

Spring Data JPA: Simplifies data access by providing repository abstractions.

Hibernate: The ORM implementation that maps objects to the database.

HikariCP: The connection pool that manages database connections efficiently.

JDBC: The fundamental API that enables Java-to-database communication.

Spring Data JPA uses Hibernate as its JPA provider, which in turn would use HikariCP for connection pooling, all of which ultimately relies on JDBC to communicate with the database.

<h3>Question 6: </h3>

@ManyToOne: Used to define a many-to-one relationship, meaning that many instances of the current entity can be associated with one instance of another entity. 
```java
// Employee Entity (The "Many" side)
@Entity
public class Employee {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    private String name;

    @ManyToOne(fetch = FetchType.LAZY) // Many employees to one department
    @JoinColumn(name = "department_id") // Specifies the foreign key column
    private Department department;

    // Getters and setters
}
```
@OneToMany: Used to define a one-to-many relationship, meaning that one instance of the current entity can be associated with many instances of another entity.
```java
@Entity
public class Department {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    private String name;

    @OneToMany(mappedBy = "department", cascade = CascadeType.ALL, orphanRemoval = true)
    private Set<Employee> employees = new HashSet<>();

    // Getters and setters
}
```
@ManyToMany: Used to define a many-to-many relationship, meaning that many instances of the current entity can be associated with many instances of another entity.
```java
@Entity
public class Student {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    private String name;

    @ManyToMany(cascade = { CascadeType.PERSIST, CascadeType.MERGE })
    @JoinTable(name = "student_course",
               joinColumns = @JoinColumn(name = "student_id"),
               inverseJoinColumns = @JoinColumn(name = "course_id"))
    private Set<Course> courses = new HashSet<>();
}

@Entity
public class Course {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    private String title;

    @ManyToMany(mappedBy = "courses")
    private Set<Student> students = new HashSet<>();

}
```
mappedBy: indicates which side of the relationship is the inverse (or non-owning) side. 
cascade: defines how lifecycle operations (like persist, merge, remove) on a parent entity should be propagated to its related child entities.
fetch: determines how the related entity or collection of entities is loaded from the database.

<h3>Question 7: </h3>
CascadeType.ALL applies parent entity operations to its children, while orphanRemoval = true deletes a child entity if it's removed from the parent's collection.

PERSIST: When you save a new parent entity, any new child entities associated with it are also saved to the database.

MERGE: When you update a detached parent entity, the changes are merged back into the database. This also applies to any changes made to its children.

REMOVE: When you delete a parent entity, all of its associated child entities are also deleted.

REFRESH: If you want to discard any changes made to a parent entity and reload its state from the database, this will also reload the state of its children.

DETACH: If you remove the parent entity from the persistence context, its children are also detached. 

<h3>Question 8: </h3>
Eager Fetching loads an entity and all its related data immediately in a single database query. Use EAGER when you are certain you will always need the related data whenever you query the parent entity. 

Lazy Fetching loads only the main entity first. The related data is fetched from the database only when you explicitly access it for the first time. Use LAZY whenever you don't need the related data in every use case.

<h3>Question 10: </h3>
The @Query annotation lets you define custom database queries directly on your Spring Data repository interface methods, overriding the default query generation.

It's used when the query you need is too complex for Spring Data to generate from the method name alone.
JPQL Example: 
```java
@Query("SELECT e FROM Employee e WHERE e.departmentName = :dept AND e.hireDate > :date")
List<Employee> findEmployeesByDeptAndHireDate(
    @Param("dept") String departmentName,
    @Param("date") LocalDate hireDate
);
```
Native Query Example:
```SQL
@Query(
  value = "SELECT * FROM employees WHERE department_name = :dept AND hire_date > :date",
  nativeQuery = true)
List<Employee> findEmployeesByDeptAndHireDateNative(
    @Param("dept") String departmentName,
    @Param("date") LocalDate hireDate
);
```

A Hibernate Session is a short-lived object that represents a single conversation between your application and the database. The SessionFactory is a long-lived, thread-safe object that creates and manages these Session objects.

<h3>Question 13: </h3>
A transaction is a single, logical unit of work that groups one or more database operations together. It guarantees that either all of the operations succeed, or none of them do. 

Spring manages the transaction's lifecycle, while Hibernate handles the actual database work within that transaction.

<h3>Question 14: </h3>
Hibernate uses a multi-level caching strategy to improve application performance by reducing the number of database queries.

The First-Level Cache is the Session cache. It's a mandatory, short-lived cache that exists for the duration of a single Hibernate Session.

The Second-Level Cache is an optional, application-wide cache that is bound to the SessionFactory lifecycle. Its purpose is to share data across different sessions and even different users.
