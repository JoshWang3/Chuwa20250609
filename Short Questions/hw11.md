## Testing Related Concepts

### 1. Unit Testing
Unit testing focuses on testing individual components or functions in isolation. It's the smallest testable part of an application.
- **Example**: Testing a single method like `calculateTax()` with various inputs to ensure it returns correct tax amounts.

### 2. Functional Testing
Functional testing verifies that software features work according to business requirements. It tests the functionality without considering internal structure.
- **Example**: Testing if a login form correctly validates credentials and redirects users to the dashboard.

### 3. Integration Testing
Integration testing checks how different modules or services work together. It identifies issues in the interaction between integrated units.
- **Example**: Testing if the payment service correctly communicates with the inventory service to update stock after a purchase.

### 4. Regression Testing
Regression testing ensures that new code changes don't break existing functionality. It's performed after code updates.
- **Example**: After adding a new discount feature, running tests to ensure the original checkout process still works correctly.

### 5. Smoke Testing
Smoke testing is a quick, basic test to check if the critical functions work. It's like a "sanity check" before deeper testing.
- **Example**: After deployment, checking if the homepage loads, users can log in, and basic navigation works.

### 6. Performance Testing
Performance testing evaluates how the system performs under expected load conditions. It measures speed, responsiveness, and stability.
- **Example**: Testing if an e-commerce site can handle 1000 concurrent users browsing products without slowing down.

### 7. Stress Testing
Stress testing pushes the system beyond normal capacity to find breaking points. It identifies the maximum load the system can handle.
- **Example**: Gradually increasing users on a video streaming platform until the servers crash, finding it fails at 50,000 concurrent streams.

### 8. A/B Testing
A/B testing compares two versions of a feature to determine which performs better with real users.
- **Example**: Showing 50% of users a green "Buy Now" button and 50% a red one, then measuring which color gets more clicks.

### 9. End-to-End Testing
End-to-end testing validates the entire application flow from start to finish, simulating real user scenarios.
- **Example**: Testing an online shopping journey from searching products, adding to cart, checkout, payment, to order confirmation email.

### 10. User Acceptance Testing (UAT)
UAT is performed by actual users or clients to verify the software meets their requirements before release.
- **Example**: Bank employees testing a new loan application system to ensure it fits their workflow before going live.

## Environment Related Concepts

### 1. Development (Dev)
The environment where developers write and initially test their code. It's unstable and frequently changing.
- **Characteristics**: Latest code, debugging tools enabled, mock data, frequent crashes acceptable
- **Example**: Developer's local machine running the app with test database

### 2. QA (Quality Assurance)
Dedicated environment for testing team to perform various tests. More stable than dev but still for testing.
- **Characteristics**: Stable builds, test data, logging enabled, isolated from production
- **Example**: qa.myapp.com with test payment gateways and sample user accounts

### 3. Pre-prod/Staging
Mirror of production environment used for final testing. Should be identical to production.
- **Characteristics**: Production-like data, same infrastructure, final validation, performance testing
- **Example**: staging.myapp.com with anonymized production data and same server specs

### 4. Production (Prod)
The live environment where real users access the application. Must be stable and secure.
- **Characteristics**: Real user data, high availability, monitoring, restricted access
- **Example**: www.myapp.com with actual customer data and payment processing

## Environment Comparison

|--------|-------------|----|---------|-----------|

| Data | Mock/Test | Test | Production-like | Real |
| Access | Developers | Dev + QA | Limited Team | End Users |
| Updates | Multiple daily | Daily | Weekly | Scheduled |
| Purpose | Code writing | Testing | Final validation | Live service |
