 3. Explain why do we need model mappers in Spring, and in what scanrios we need it.
    Model mappers in Spring are used to simplify the mapping process between objects, especially when converting between business entities and Data Trasnfer Objects(DTOs). This is crucial for separating concerns and ensuring clean code architecture in applications

    Secaniros:
    1. Mapping Between layers: when converting data between the persistence layers(entities) and service/controller layers(DTOs)
    2. Complex Object Mapping: When object have nested structures or require custom transformations
    3. Reducing Boilerplate Code: Instead of writing repetitive mapping code manually, model mappers automate the process

 4. Provide 3 examples in which model mapper will NOT map succesfully, explain why.
    1. Mismatched Field Names: If the source and target objects have fields with different names, ModelMapper will not map them unless explicitly cofigured.
```java
// Source class
public class UserEntity{
    private String firstName;
    private String lastName;
}

// Target class
public class UserDTO{
    private String first_name;
    private String last_name;
}

// Mapping
ModelMapper modelMapper = new ModelMapper();
UserEntity userEntity = new UserEntity();
userEntity.setFirstName("John");
userEntity.setLastName("Doe");

UserDTO userDTO = modelMapper.map(userEntity, useDTO.class);

// Output: userDTO.first_name and userDTO.last_name will remain null

// Solution:
modelMapper.typeMap(UserEntity.class, UserDTO.class).addMappings(mapper -> {
    mapper.map(UserEntity::getFirstName, UserDTO::setFirst_name);
    mapper.map(UserEntity::getLastName, UserDTO::setLast_NAME);
});

```
    ModelMapper relies on matching field names by default. Since `firstName` does not match `first_name`, no mappig occurs.

    2. Complex Nested Objects: ModelMapper struggles with deeply nested objects unless explicitly configured.
```java
// Source classes
public class UserEntity{
    private String name;
    private AddressEntity address;
}

public class AddressEntity{
    private String street;
    private String city;
}

// Target class
public class UserDTO{
    private String name;
    private String street;
    private String city;
}

// Mapping
ModelMapper modelMapper = new ModelMapper();
UserEntity userEntity = new UserEntity();
userEntity.setName("John");
AddressEntity address = new AddressEntity();
address.setStreet("123 Main St");
address.setCity("Springfield");
userEntity.setAddress(address);

UserDTO userDTO = modelMapper.map(userEntity, UserDTO.class);

// Output: userDTO.street and userDTO.city will remain null

// Solution:
modelMapper.typeMap(UserEntity.class, UserDTO.class).addMappings(mapper -> {
    mapper.map(src -> src.getAddress().getStreey(), UserDTO::setStreet);
    mapper.map(src -> src.getAddress().getCity(), UserDTO::setCity);
});

```
    ModelMapper does not automatically flatten nested objects into a single target object unless explicitly configured with a custom mapping.

    3. Custom Transformations: When a field in the source object requires transformation. ModelMapper will fail without a custom converter.
```java
// Source class
public class UserEntity{
    private Date birthDate;
}

// Target class
public class UserDTO{
    private String birthDate;
}

// Mapping
ModelMapper modelMapper = new ModelMapper();
UserEntity userEntity = new UserEntity();
userEntity.setBirthDate(new Date());

UserDTO userDTO = modelMapper.map(userEntity, UserDTO.class);

// Output: userDTO.birthDate will remain null

// Solution:
modelMapper.addConverter(new Converter<Date, String>(){
    public String convert(MappingContext<Date, String> context){
        return new SimpleDateFormat("yyyy-MM-dd").format(context.getSource());
    }
});

```
    ModelMapper cannot automatically convert a `Date` to a `String` unless a custom converter is provided.

 5. Explain how model mapper cast different data types between source object and target class.


 7. Explain how Controller Advices work, is there any other approach to do same/similar global API exception handling?
 Controller Advices in Spring are used for global exception handling across the application. They work by intercepting exceptions thrown in controllers and providing a centralized way to handle them.
```java
@ControllerAdvice
public class GlobalExceptionHandler{
    @ExceptionHandler(ResourceNotFoundException.class)
    public ResponseEntity<ApiErrorResponse> handleResourceNotFound(ResourceNotFoundException ex){
        ApiErrorResponse response = new ApiErrorResponse();
        response.setStatus(HttpStatus.NOT_FOUND.value());
        response.setMessage(ex.getMessage());
        response.setTimestamp(LocalDateTime.now().toString());
        return new ResponseEntity<>(response, HttpStatus.NOT_FOUND);
    }
}
```

 11. Explain different types of dependency injection, explain their suitable use cases, and why fielde injection is not recommended  in general. Please provide necessary code snippets and screenshots if possible.
    1. Constructor Injection: Preferred for mandatory dependencies
```java

public class Service{

        this.repository = repository;
    }

}
```
    2. Setter InjectionL Suitable for optional dependencies
```java

    @Autowired
    public void setRepository(Repository repository){
        this.repository = repository;
    }
}
```
