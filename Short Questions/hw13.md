## Test Related:
Unit Testing - Tests individual components or functions in isolation
e.g. Testing a calculateTax(price, rate) function to verify it returns the correct tax

Functional Testing - Verifies that software functions according to specified requirements
e.g. Testing a tax preparation software feature by verifying that users can log in with valid credentials, get error messages with invalid credentials, and are redirected to the correct page after successful login.

Integration Testing - Tests the interaction between integrated components or systems to ensure they work together correctly.
e.g. Testing how a tax preparation component communicates with the payment processing service. 

Regression Testing - Re-runs previously passed tests to ensure new code changes haven't broken existing functionality.
e.g. After adding a new feature to tax preparation, you re-run all existing tests for login, calculation, bill payments, etc.. to ensure these features still work as expected.

Smoke Testing - Basic testing to verify the most critical functions work.
e.g.After deploying a web application, smoke tests might check if the homepage loads, users can log in, and the database connection works. 

Performance Testing - Evaluates how a system performs under normal expected load conditions, measuring response times, throughput, and resource utilization.
e.g. Testing a tax preparation web app to ensure it loads within 3 seconds when 1,000 concurrent users are filing form, and measuring server CPU and memory usage during normal traffic patterns.

Stress Testing - Tests system behavior under extreme conditions beyond normal capacity to find breaking points.
e.g. Gradually increasing concurrent users on a tax preparation web app from 1,000 to 10,000 to 50,000 until the system crashes or becomes unresponsive, identifying the maximum load it can handle.

A/B Testing - Compares two versions of a feature or interface with real users to determine which performs better.
e.g. Showing 50% of users a blue "Buy Now" button and 50% a red "Buy Now" button on a product page, then measuring which color generates more purchases over two weeks.

End-to-End Testing - Tests complete user workflows from start to finish in a production-like environment.
e.g. Testing the entire process of a user use a tax preparation web app, filling forms, making payment, and receiving confirmation, etc..

User Acceptance Testing (UAT) - Final testing phase where actual users validate that the system meets business requirements and is ready for production use.
e.g. Having real user test a new tax preparation web app in a controlled environment, performing tasks like filling forms, making payment, etc. to ensure the app meets their needs before public release.

## Environment related:
Development - Where developers write, test, and debug code on their local machines or shared development servers.
e.g. Developer build and run tax preparation app locally

QA (Quality Assurance) - Dedicated environment where QA teams perform systematic testing of features and bug fixes.
e.g. QA team tests the tax preparation feature with automated test cases. 

Pre-prod/Staging - Production-like environment used for final validation before release, closely mimicking production setup.
e.g. Tax preparation app deployed to staging with a database containing 1000000 forms, real payment pipeline. 

Production - Live environment where real users access the application and conduct actual business.
e.g. Customers use the app to do real tax preparation.
