 Testing related:
 1. Unit Testing
    * Definition: Focuses on testing individual components or methods in isolation.
    * Example: Testing a method in `PostServiceImpl` that adds a comment to a database
    * Comparison: Unlike Integeration Testing, Unit Testing does not involve dependencies like database or external APIs.
 2. Functional Testing
    * Definition: Validates the functionality of the application against requirements
    * Example: Checking if the comment feature works as expected when submitting a comment
    * Comparison: Broader than Unit Testing, as it tests features end-to-end without focusing on code structure

 3. Integration Testing
    * Definition: Tests how different modules or services work together
    * Example: Testing the interaction between `CommentServiceImpl` and the database layer
    * Comparison: Unlike Unit Testing, it involves multiple components interacting

 4. Regression Testing
    * Definition: Ensures that new code changes do not break existing functionality
    * Example: Running all tests after adding a new feature to `CommentServiceImpl`
    * Comparison: Focuses on stability over time, whereas Functional Testing focuses on correctness

 5. Smoke Testing
    * Definition: A high-level test to ensure basic functionality works
    * Example: Verifying that the application starts and the comment feature is accessible
    * Comparison: Less comprehensive than Functional Testing, as it only checks critical paths

 6. Performance Testing
    * Definition: Measures the application's responsiveness and stability under load
    * Example: Testing how the comment feature handles thousands of simultaneous requests
    * Comparison: Focuses on speed and resource usage, unlike Functional Testing

 7. Stress Testing
    * Definition: Tests the application's behavior under extrem conditions
    * Example: Overloading `CommentServiceImpl` with excessive requests to check for failure points
    * Comparison: Goes beyound normal load, unlike Performance Testing

 8. A/B Testing
    * Definition: Compares two versions of a feature to dertmine which performs better
    * Example: Testing two UI designs for the comment feature
    * Comparison: User-focused, unlike other technical tests

 9.  End-to-End Testing
    * Definition: Validates the entire workflow of the application
    * Example:Testing submitting a comment, storing it in the database, and displaying it on the UI
    * ComparisonL Covers more ground than Integeration Testing, including front-end and back-end

 10. User Acceptance Testing
    * Definition: ensures the application meets user requirements
    * Example: Having user test the comment feature for usability and correctness
    * ComparisonL Unlike other tests, UAR is conducted by end-users, not developers

 Environment related:
 1. Development
    * Definition: The enviroment where developers write and test code
    * Example: Running Unit Tests for `CommentServiceImpl`
    * Comparison: Less stable than QA, as code changes frequently

 2. QA (Quality Assurance)
    * Definition: The environment used for testing the application
    * ExampleL: Running Integration Tests and Regression Test for `CommentServiceImpl`
    * Comparison: More stable than Development, but not ready for user access

 3. Pre-prod/Staging
    * Definition: A replica of the Production environment for final testing
    * Example: Running End-to-End Tests for the comment feature
    * Comparison: Closest to Production but used for testing

 4. Production
    * Definition: The live environment where users interact with the application
    * Example: Monitoring performance of the comment feature under real-world conditions.
    * ComparisonL Unlike other environments, changes here directly affect users.
