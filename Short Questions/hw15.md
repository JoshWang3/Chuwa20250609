1. Explain monolithic architecture, service oriented architecture and Micro service architecture.
    * Monolithic Architecture
      * Definition: A monolithic application is a single unified codebase where all components are tightly coupled and run as a single unit
      * Key Characteristics: 
        * Single deployable unit
        * Difficult to scale individual component; scaling requires scaling the entire application
        * Tight coupling between modules makes it harder to adopt new technologies
        * Maintenance becomes challenging as the application grows
    * Service-Oriented Architecture(SOA)
      * Definition: SOA is an architectural style that organizes software systems as a collection of loosely coupled services that communicate via standardized interfaces
      * Key Characteristics:
        * Services can be resured across different applications
        * Communication often involves middleware like an Enterprise Service Bus
        * Focus on interoperability and reusability
        * Can suffer from heavy communication overhead dur to ESB
    * Microservice Architecture
      * Definition: Microservice architecture is an approach to building applications as a collection of small, independently deployable services that communicate via lightweight protocols
      * Key characteristics:
        * Each microservice focuse on a single business capability
        * Decentrailized data management; each service can have its own database
        * Scalability and fault isolation at the service level
        * Requires DDevOps practices for deployment and monitoring
  
2. Document the microservice architeture and core components
    Microservices architecture breaks down an application into small services, each responsible for a specific functionality. These services interact via APIs.

    Core Component:
    1. API Gateway: Acts as a single entry point for clients; Handles request routing, authenticattion, rate limiting, etc.
    2. Service Discovery: Enable services to locate each other dynamically
    3. Service Registry: Maintains a list of available services
    4. Load Balancer:Distributes incoming request across multiple instances of a service
    5. Distributed Database: Each service can have its own database
    6. Resilience and Fault Tolerance: Prevent cascading failures
    7. Configuration Management: Centralized configuration of services
    8. Monitoring and Logging: Tracks the health and performance of services

3. Explain Resilience patterns? Explain circuit breaker with Spring Cloud Hystrix code example.
    **Resilience patters** aim to make applications fault-tolerant and ensure they continue operating despite failures. Common pattern include:
    1. Retry: Automatically retry failed operations
    2. Fallback: Provide an alternative response when an operatin fails
    3. Circuit Breaker: Prevent repeated failures by temporarily halting requests to a failing service
    4. Bulkhead: Isolate failures to prevent them from affecting other parts of the system
    5. Rate limiting: Control the number of requests to avoid overwhelming a service

    **Circuit Breaker Pattern** monitors service calls and opens the circuit(halts requests) if failures exceeed a threshold. It then retries periodically until the service recovers.

4. Explain load balancing algorithms.
    Load balancing algorithms distribute incoming requests across multiple servers or service instances. Common algorithms includes:
    1. Round Robin:
       1. Distributes requests sequentially to each server
       2. Simple and effective for similar server configurations
    2. Least Connections
       1. Sends requests to the server with the fewest active connections
       2. Useful for servers with varying capabilities
    3. IP Hash
       1. Uses a hash of the client's IP address to consistently rout requests to the same server
       2. Ensures session persistence
    4. Weighted Round Robin: assignes weights to server based on their capacity and routes requests accordingly
    5. Random: distributes requests randomly across server
   
5. Explain API Gateway.
    An API Gateway is a server that acts as a single entry point for all client requests to microservices. It handles tasks such as routing, authentication, rate limiting, and response aggregation.

    Key features:
    1. Request routing to appropriate microservices
    2. Authentication and authorization
    3. Load balancing
    4. Caching
    5. Response transformation
    6. Monitoring and logging

6. Explain service discovery and service registry
    Service discovery: it allows services to dynamically locate each other without hardcoding their locations. It ensures scalability and flexibility in microservices architecture.

    Service registry: The Service Registry is a database of available services and their instances. Service register themselves when they start and deregister when they shut down
