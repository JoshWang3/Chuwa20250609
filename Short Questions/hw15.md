## Question 1

Monolithic architecture: entire application is built as a single, unified unit. All components are interconnected and deployed together as one package.

Service oriented architecture: functionality is organized into discrete services that communicate over a network. 

Microservices architecture: breaks down applications into small, independent services that handle specific business functions. Each service runs in its own process, communicates via lightweight protocols. 

## Question 2
1. API Gateway: the single entry point for all client requests and acts as a reverse proxy to route requests to appropriate microservices.
2. Service registry: maintains a database of available service instances and their locations. 
3. Service discovery: enables services to find and communicate with each other dynamically.
4. Load balancing: distributes incoming requests across multiple service instances. 
5. Circuit breaker: prevents cascading failures by monitoring service calls and failing fast when a service becomes unavailable.

## Question 3
Resilience patterns: design strategies that help distributed systems handle failures gracefully and maintain availability even when individual components fail.
- Circuit Breaker
```java
@Service
public class UserService {
    
    @Autowired
    private RestTemplate restTemplate;
    
    @HystrixCommand(fallbackMethod = "defaultUser")
    public String getUser(int id) {
        String url = "http://localhost:9999/user/" + id; 
        return restTemplate.getForObject(url, String.class);
    }
    
    public String defaultUser(int id) {
        return "Default User " + id;
    }
}
```
- Retry: Automatically retries failed operations with configurable strategies like exponential backoff and jitter. 
- Timeout: Sets time limits on operations to prevent indefinite waiting and resource exhaustion.
- Bulkhead: Isolates critical resources by partitioning them into separate pools. 
- Fallback: Provides alternative responses or degraded functionality when primary service calls fail.

## Question 4

Round Robin: Distributes requests sequentially across all available servers in a circular order.

Least Connections: Routes requests to the server with the fewest active connections.

Least Response Time: Routes requests to the server with the lowest average response time and fewest active connections.

IP Hash: Uses a hash of the client's IP address to determine which server handles the request.

Location-Based: Routes requests to servers based on geographic proximity.
