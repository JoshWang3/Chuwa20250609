## Explain monolithic architecture, service oriented architecture and Micro service architecture.
- Monolithic architecture: Integration of all kinds of functionalities/services into a single deployable unit. It can become messy and hard to maintain as the application grows.

- Service oriented architecture: Organizes business functions as reusable services with standardized interfaces. Services are larger, shared across applications, use heavy protocols (SOAP/XML), may share databases.

- Micro service architecture: Divides applications into small independent services. Each service has specific scope, separate deployment, owns data, lightweight communication (REST/APIs). Used in e-commerce and distributed systems.



## Document the microservice architeture and core components
- API gateways: a single entry point for clients, routing requests authentication, rate limiting, load balancing.
- service registries: services register their location and status to a central registry.
- service discovery: services query the registry to find other services' addresses. 
- load balancing: distributes incoming traffic across multiple instances of a microservice.
- circuit breakers: a design pattern that prevents cascading failures by stopping calls to failing services.
- Database per service: each microservice owns and manages its own database independently.
- Inter-service communication: services communicate through REST APIs, message queues, or event streaming.
- Centralized logging: aggregates logs from all services into a single system for analysis.
- CI/CD: automatic builds, tests and deployment services.

## Explain Resilience patterns? Explain circuit breaker with Spring Cloud Hystrix code example.
- Resilience pattern: Design patterns that help microservices handle failures gracefully and maintain system stability under adverse conditions. Hystrix (a library) implements typical resilience patterns (timeouts).
Resilience pattern contains: 
1. Circuit Breaker: Stops calls to failing services when failure threshold is reached.
2. Retry Pattern: Automatically retries failed requests with backoff strategies.
3. Timeout Pattern: Sets maximum wait time for service responses to prevent hanging.
4. Bulkhead Pattern: Isolates resources to prevent one failure from affecting others.
5. Fallback Pattern: Provides alternative responses when primary service fails.
6. Rate Limiting: Controls request volume to prevent service overload.
...

```java
// enable Hystrix
@SpringBootApplication
@EnableCircuitBreaker  //打开hystrix
public class DemoApplication{
	public static void main(String[] args){
		SpringApplication.run(DemoAlllication.class, args);
	}
}
```
```java
// create a service with @HystrixCommand
@Service
public class paymentService{
	@Autowired
	private RestTemplate restTemplate;

	@HystrixCommand(fallbackMethod = "paymentFallback");
	public String processPayment(String orderId){
		return restTemplate.getForObject("http://payment-service/pay/" + orderId, String.class);
	}
	public String paymentFallback(String orderId) {
        return "Payment service unavailable for order: " + orderId;
    }
}

```

- 调用 processPayment() 
-> Hystrix 代理拦截

-> 检查 Circuit Breaker 状态

-> 如果 CLOSED → 执行原方法 (restTemplate.getForObject)

-> 如果 OPEN → 直接调用 paymentFallback()

-> 监控成功/失败次数

-> 达到阈值 → 自动 OPEN/CLOSE circuit
