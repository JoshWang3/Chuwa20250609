## 1. Explain monolithic architecture, service-oriented architecture, and microservice architecture

### Monolithic Architecture
- A single-tiered application where all components (UI, business logic, data access) are packaged together.
- Tight coupling; any change requires redeployment of the entire application.
- Difficult to scale and maintain as the application grows.

### Service-Oriented Architecture (SOA)
- Applications are composed of services that communicate over a network using protocols like SOAP.
- Encourages reusability and interoperability between services.
- Typically heavier than microservices due to reliance on ESB (Enterprise Service Bus).

### Microservice Architecture
- Decomposes applications into small, independent services focused on single business capabilities.
- Services communicate over lightweight protocols like HTTP/REST or messaging queues.
- Each service can be developed, deployed, and scaled independently.

## 2. Document the microservice architecture and core components

### Key Components
- **Service**: Self-contained business functionality.
- **API Gateway**: Entry point for client requests; handles routing, authentication, and rate limiting.
- **Service Registry**: Keeps track of service instances and their availability.
- **Config Server**: Centralized configuration management (e.g., Spring Cloud Config).
- **Discovery Server**: Allows dynamic registration and discovery of services (e.g., Eureka).
- **Load Balancer**: Distributes traffic across services (e.g., Ribbon, Spring Cloud LoadBalancer).
- **Resilience Module**: Handles fault tolerance (e.g., Hystrix, Resilience4j).
- **Messaging**: For asynchronous communication (e.g., Kafka, RabbitMQ).

## 3. Explain Resilience patterns? Explain circuit breaker with Spring Cloud Hystrix code example

### Common Resilience Patterns
- **Circuit Breaker**: Prevents system overload by breaking the call chain to a failing service.
- **Retry**: Automatically retries failed operations.
- **Bulkhead**: Isolates failures to prevent cascading.
- **Timeout**: Limits waiting time for a response.

## 4. Explain Load Balancing Algorithms

Load balancing distributes incoming requests across multiple instances to improve responsiveness and availability.

### Common Algorithms:
- **Round Robin**  
  Distributes requests cyclically: A → B → C → A → ...
  
- **Random**  
  Randomly picks an instance.

- **Least Connections**  
  Chooses the instance with the fewest active connections.

- **Weighted Round Robin / Least Connections**  
  Uses weights to prefer stronger servers (e.g., 2x CPU gets 2x requests).

- **IP Hashing**  
  Routes traffic based on client IP address.

### Types:
- **Client-Side Load Balancing** (e.g., Spring Cloud LoadBalancer, Ribbon)  
  The client queries a service registry and chooses an instance locally.

- **Server-Side Load Balancing** (e.g., NGINX, HAProxy)  
  The load balancer sits between clients and services.

## 5. Explain API Gateway

An API Gateway is a single entry point into the system that handles requests from clients and routes them to the appropriate microservices.

### Responsibilities:
- Routing requests to appropriate microservices.
- Authentication and authorization.
- Rate limiting and throttling.
- Caching.
- Load balancing (sometimes).
- Logging and monitoring.

### Common Tools:
- **Spring Cloud Gateway**  
- **Netflix Zuul**  
- **Kong**  
- **NGINX**

---

## 6. Explain Service Discovery and Service Registry

### Service Registry:
A centralized database that keeps track of all service instances and their addresses.

- Services register themselves upon startup.
- Services deregister upon shutdown.

### Service Discovery:
Allows clients or gateways to find services dynamically.

#### Types:
- **Client-Side Discovery**  
  The client queries the registry directly and selects a service (e.g., Ribbon with Eureka).

- **Server-Side Discovery**  
  The API Gateway or Load Balancer queries the registry and forwards the request (e.g., AWS ALB).

### Tools:
- **Eureka**
- **Consul**
- **Zookeeper**
