## 1. Explain monolithic architecture, service oriented architecture and Micro service architecture.

* monolithic architecture: put everything (code) together, as a whole
  
    Definition:
A monolithic architecture is a single unified application where all components (UI, business logic, database access, etc.) are part of one codebase and run as a single service.

    Example:
An e-commerce app with user login, product catalog, and payment processing all in one program.
* Service Oriented Architecture: 
api: SOAP + other xml

    Definition:
SOA is a design pattern where the application is composed of interconnected services, often communicating over a network using SOAP or REST. Each service provides a specific business functionality.

    Example:
An online travel booking system where flight, hotel, and car rental services interact via a centralized Enterprise Service Bus (ESB).
* Micro service architecture: 
 Microservice is an architecture design pattern. It splits one large application into multiple small and
independent service based applications. Each service only does one thing.

    Definition:
Microservices is an evolution of SOA. It breaks down the application into small, independent services, each responsible for a specific functionality, communicating over lightweight protocols like HTTP/REST or gRPC.

    Example:
A video streaming platform with separate services for user auth, video processing, recommendations, and payments—each service can be deployed and scaled independently.


## 3. Explain Resilience patterns? Explain circuit breaker with Spring Cloud Hystrix code example.

* Resilience Patterns: Resilience patterns are design strategies used in microservices to handle failures gracefully and maintain system stability.

* Circuit Breaker: define backup/Fallback behavior when one or more micro-service is/are unavailable/timeout
  
* A Circuit Breaker monitors service calls and opens the circuit (blocks calls) if failures exceed a threshold. After a cooldown period, it allows some traffic to test if recovery is possible.


* Enable Circuit Breaker
```
@SpringBootApplication
@EnableCircuitBreaker
public class Application {
    public static void main(String[] args) {
        SpringApplication.run(Application.class, args);
    }
}

```


* Service Class
  
```
@HystrixCommand(fallbackMethod = "fallbackMethod")
public String mainMethod() {
    // Try risky operation (like a remote API call)
    throw new RuntimeException("Fail!");
}

public String fallbackMethod() {
    // Backup plan
    return "Service unavailable. Try again later.";
}

```


## 4. Explain load balancing algorithms.
balancing requests to multiple deploying units (servers) of the same service.


When many requests come in, a load balancer decides which server or service instance should handle each one, so that no single server gets overwhelmed.


Common Load Balancing Algorithms
1. Round Robin
* Assigns requests to servers one by one in a circular order

* Easy to implement

 * Example:
Server A → B → C → A → B → C...

2. Weighted Round Robin
* Like Round Robin, but gives more requests to more powerful servers

 * Example:
  
    Server A (weight 3), Server B (weight 1)

    Pattern: A → A → A → B → A → A → A → B...

3. Least Connections
* Sends traffic to the server with the fewest active connections

* Good when request processing time varies

* Example:
If Server A has 2 connections and Server B has 5 → send next request to Server A

4. Token Bucket
* Rate-limiting algorithm (not a routing method)

* Each server has a bucket of tokens. Each request uses a token.

* If no tokens left, request is delayed or denied.

* Used for: controlling traffic rate, not choosing servers
(e.g., limit 100 requests per minute per IP)

5. Geo-Based (Geolocation Routing)
* Directs traffic based on the user’s location to the nearest or most appropriate data center/server.

* Example:

    A user from Japan → routed to Tokyo server

    A user from Germany → routed to Frankfurt server

6. Random
* Picks a server at random

* Simple, but can result in uneven traffic

## 5. Explain API Gateway.

route incoming requests (from external network) to different internal services.

Instead of clients calling each microservice directly, they go through the API Gateway, which:

* Routes the request to the correct service
* Applies security checks
* Aggregates data if needed
* Handles logging, rate limiting, and monitoring

## 6. Explain service discovery and service registry

* Service Discover: Service Discovery is the automatic process of finding services in a networked system.


    When you have many microservices (e.g., UserService, OrderService, PaymentService), each running on different machines or containers, their locations (IP/Port) may change frequently due to:

    * Auto-scaling

    * Container restarts

    * Failures

    Service Discovery helps services find and communicate with each other without hardcoding addresses.

* Service Registry: 
A Service Registry is the central database where all services register themselves with their name, IP address, port, and metadata.

    It’s like a phonebook for services.
