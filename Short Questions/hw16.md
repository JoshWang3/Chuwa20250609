**topic** - logical channel or category where messages are published.
- the fundamental unit of organization in Kafka, allowing **producers** to write data and **consumers** to read data from specific streams
- each topic is divided into one or more **partitions** -  actual storage units, allowing Kafka to distribute data across multiple **brokers**. 
- - **offset** - unique sequential identifier for each message within a partition

broker - Kafka server that stores and serves data. Handle all requests from **producers** (to write data) and **consumers** (to read data), 



consumer group - collection of consumer instances that work together to consume messages from topics. A consumer instance is a single running process or thread that reads messages from Kafka topics.

producer - client application that publishes messages to Kafka topics. 

**Zookeeper** - manages cluster metadata and coordination. Stored information about brokers, topics, partitions, and consumer group coordination.



## Question 1
N>=M - Each consumer gets at least one partition (some may get multiple). All partitions are consumed.

N<M - Some consumers remain idle with no partitions assigned. Only N consumers will be active.

## Question 2
Brokers store topic partitions and their replicas. Each broker hosts a subset of partitions from various topics.

## Question 3
Consumers actively pull messages from topics. 

## Question 4
Enable exactly-once semantics with enable.idempotence=true. 

## Question 5
When consumers fail, Kafka triggers a rebalance and redistributes the failed consumer's partitions to remaining active consumers. There will be no data loss since messages stay stored in Kafka. 

## Question 6
Messages remain stored in Kafka brokers according to the topic's retention policy, waiting for the consumers to be back online, so no data loss. 

## Question 7
Consumer lag - difference between the latest message offset in a partition and the consumer's current offset. 
Resolved by: 
- consumer configuration tuning
- horizontal scale up of the consumers

## Question 8
Through offsets, each message gets a sequential offset number within its partition, consumers commit their current offset position to Kafka.
