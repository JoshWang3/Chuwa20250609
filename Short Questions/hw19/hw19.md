3. Compare let vs var, explain variable hoisting with your own code examples.

   **Scope**:

   - **`var`**: Has **function scope** or **global scope** if declared outside a function. It is not block-scoped, meaning it is accessible throughout the entire function, regardless of block statements (like `if` statements or `for` loops) within that function.

   - **`let`**: Has **block scope**, meaning it is only accessible within the block (e.g., loops, conditionals, etc.) where it is declared.

     ```javascript
     if (true) {
       var x = 30;
       let y = 40;
     }
     console.log(x);  // 30, because var is function-scoped or globally scoped.
     console.log(y);  // ReferenceError: y is not defined, because let is block-scoped.
     ```

   **Re-declaration**:

   - **`var`**: Can be redeclared in the same scope.

   - **`let`**: Cannot be redeclared in the same scope, leading to an error.

     ```javascript
     var z = 50;
     var z = 60;  // No error, var allows re-declaration.
     console.log(z);  // 60
     
     let w = 70;
     let w = 80;  // SyntaxError: Identifier 'w' has already been declared.
     ```

   **Hoisting** - the automatical behavior of variable declarations(using `var`, `let`, `const`) being moved to the top of their scope during the compile phase, before the code is executed, which means **allowing us to use variables before they are declared**. Hoisting only affects declarations, not initializations.

   - **`var`**: Variables declared with `var` are hoisted to the top of their scope and initialized with `undefined`. This means they can be referenced before their actual declaration line, but will return `undefined` if accessed before assignment.

   - **`let`**: Variables declared with `let` are also hoisted but are not initialized. Accessing them before the declaration line results in a **ReferenceError** due to the "temporal dead zone."

     ```javascript
     console.log(a);  // undefined, because `a` is hoisted but not initialized yet.
     var a = 10;
     console.log(a);  // 10, after assignment.
     
     console.log(b);  // ReferenceError: Cannot access 'b' before initialization
     let b = 20;
     console.log(b);  // 20, after assignment.
     ```

     

4. Explain closure with code example.

   A closure gives an inner function **access to its outer function's scope**, even after the outer function has finished executing.

   A closure is created:

   - Inner function
   - Inner function uses the variable from outer function
   - Outer function returns inner function

   ```javascript
   function outer() {
       let count = 0;  // Variable in outer function
   
       // Inner function (closure)
       function inner() {
           count++;  // Uses `count` from the outer function's scope
           console.log(count);
       }
   
       return inner;  // Returning the inner function (closure)
   }
   
   const counter = outer();  // `counter` now references the inner function
   counter();  // Logs: 1
   counter();  // Logs: 2
   counter();  // Logs: 3
   
   ```

   It is kind of like class attributes in Java used for data encapsulation, but it is tied to the scope of functions, while class attributes are tied to object instances or the class itself.

   

5. Explain Callback Hell with code example.

   Callback Hell (also known as Pyramid of Doom) refers to a situation where you have multiple **nested callbacks** in asynchronous JavaScript code.

   ```javascript
   // Simulating an asynchronous operation with setTimeout
   function task1(callback) {
       setTimeout(() => {
           console.log('Task 1 completed');
           callback();
       }, 1000);
   }
   
   function task2(callback) {
       setTimeout(() => {
           console.log('Task 2 completed');
           callback();
       }, 1000);
   }
   
   function task3(callback) {
       setTimeout(() => {
           console.log('Task 3 completed');
           callback();
       }, 1000);
   }
   
   function task4(callback) {
       setTimeout(() => {
           console.log('Task 4 completed');
           callback();
       }, 1000);
   }
   
   // Callback hell: Multiple callbacks nested inside each other
   task1(function() {
       task2(function() {
           task3(function() {
               task4(function() {
                   console.log('All tasks completed');
               });
           });
       });
   });
   
   ```

   

6. Explain Promise, Async, Await with code examples.

   They are used to solve the issue of callback hell, which can make asynchronous code easier to read, write, and maintain.

   - **Promise**: An object representing the eventual completion (or failure) of an asynchronous operation. Can be chained with `.then()`, `.catch()`, and `.finally()`  to handle asynchronous results.

     - Promise Constructor:

       The constructor takes an executor function that contains two functions: `resolve` and `reject`.

       ```javascript
       let promise = new Promise(function(resolve, reject) {
           // Asynchronous code
           if (/* some condition */) {
               resolve(value);  // If the asynchronous was successful
           } else {
               reject(error);   // If the asynchronous failed
           }
       });
       ```

     - Promise States:

       Pending: The promise is still being executed.

       Fulfilled: The promise has been completed successfully.

       Rejected: The promise has failed.

     - Promise Methods:

       `then()`: used to specify the actions to take when a promise is **fulfilled** or **rejected**

       `catch()`: used to handle errors or rejections in a promise chain

       `finally()`: used to clean up after a promise operation

       ```javascript
       myPromise
           .then(result => console.log(result))
           .catch(error => console.log(error))
           .finally(() => console.log("Cleanup after promise"));
       
       ```

   - **Async/Await**: Built on top of Promises and allow you to write asynchronous code in a more synchronous (linear) style, making it more readable and easier to follow.

     **`async`**: Declaring a function as `async` makes it return a **Promise**.

     **`await`**: Used inside an `async` function to pause the execution of the `async` function until the promise is resolved or rejected.

     ```javascript
     function fetchDataFromAPI(url) {
         return new Promise((resolve, reject) => {
             setTimeout(() => {
                 if (url === "validURL") {
                     resolve("Data fetched successfully from API!");
                 } else {
                     reject("Failed to fetch data from API.");
                 }
             }, 1500);
         });
     }
     
     async function getData() {
         try {
             const result = await fetchDataFromAPI("validURL");  // Simulate successful API call
             console.log(result);  // "Data fetched successfully from API!"
         } catch (error) {
             console.log(error);  // If the URL is invalid, it'll log this
         }
     }
     
     getData();
     ```

       }

9. Explain how Javascript implement asynchronous non-blocking feature. Particularly: Event Loop, Macrotask, and Microtask with code samples.

   Please submit code, answers, and screenshots to your GitHub branch.

   Javascript is a single-thread language. It uses an **asynchronous non-blocking model** to handle multiple tasks concurrently. The key components responsible for this are the Event Loop, Macrotasks, and Microtasks

   **Event Loop**:

   1. The **call stack** executes synchronous code (the current function).
   2. When an asynchronous task (like a `setTimeout`, network request, or file read) is encountered, the task is moved to the **task queue** (or **callback queue**).
   3. Once the call stack is empty, the event loop will pull the first task from the task queue and push it onto the call stack for execution.
   4. Tasks are processed in the order they are added to the task queue.

   Macrotasks and Microtasks are different types in the task queue.

   | Component      | Description                                                  | Examples                                   |
   | -------------- | ------------------------------------------------------------ | ------------------------------------------ |
   | **Event Loop** | Manages the execution of code and the task queue.            | Continuously checks for tasks to run.      |
   | **Macrotasks** | Larger tasks that are executed after synchronous code and microtasks. | `setTimeout`, I/O operations, UI rendering |
   | **Microtasks** | Smaller tasks that are executed after synchronous code but before macrotasks. | **Promises** (`then`, `catch`, `finally`)  |

   **Order: synchronous code →  microtasks → macrotasks**

   ```javascript
   console.log("Start");
   
   setTimeout(function() {
       console.log("Macrotask: Timeout 1");
   }, 0);
   
   Promise.resolve().then(function() {
       console.log("Microtask: Promise 1");
   });
   
   setTimeout(function() {
       console.log("Macrotask: Timeout 2");
   }, 0);
   
   Promise.resolve().then(function() {
       console.log("Microtask: Promise 2");
   });
   
   console.log("End");
   
   ```

   ```
   Start
   End
   Microtask: Promise 1
   Microtask: Promise 2
   Macrotask: Timeout 1
   Macrotask: Timeout 2
   ```
