## 3. Custom JPA Methods and Validate Syntax

### custom JPA methods using Spring Data JPA naming conventions
```Java
// Find by exact title
List<Post> findByTitle(String title);

// Find posts where the title contains a keyword (LIKE %keyword%)
List<Post> findByTitleContaining(String keyword);

// Case-insensitive title match
List<Post> findByTitleIgnoreCase(String title);

// Match either title OR description
List<Post> findByTitleOrDescription(String title, String description);

// Match both title AND content
List<Post> findByTitleAndContent(String title, String content);

// Find posts created after a specific date/time
List<Post> findByCreateDateTimeAfter(LocalDateTime date);

// Find posts where content starts with a given prefix
List<Post> findByContentStartingWith(String prefix);
```

### Demonstrate how JPA performs compile-time syntax checks on method names
If we create the following method:
```java
List<Post> findByAuthor(String author); // ❌ Field 'author' does not exist in Post entity
```

There will be an error: `Error: No property 'author' found for type 'Post'`
since author is not a field in the Post entity

-> Spring Data JPA validates custom query method names at application startup,
ensuring correctness before the app runs -> compile-time syntax checks

## 4. Implement JPQL and Native SQL Queries

### Repository Layer - PostRepository.java
```java
// JPQL query using @Query
@Query("select p from Post p where p.title = :title" )
List<Post> getPostsByExactTitleJPQL(@Param("title") String title);

// Native SQL query using @Query(nativeQuery = true)
@Query(value = "SELECT * FROM posts p WHERE p.description LIKE %:keyword%", nativeQuery = true)
List<Post> getPostsByDescriptionKeywordSQL(@Param("keyword") String keyword);
```

### Service Interface - PostService.java
```java
// JPQL: get posts by exact title
List<PostDto> getPostsByExactTitleJPQL(String title);

// Native SQL: get posts where description contains keyword
List<PostDto> getPostsByDescriptionKeywordSQL(String keyword);
```
### Service Implementation - PostServiceImpl.java
```java
@Override
public List<PostDto> getPostsByDescriptionKeywordSQL(String keyword) {
    return postRepository.getPostsByDescriptionKeywordSQL(keyword)
            .stream()
            .map(this::mapToDTO)
            .collect(Collectors.toList());
}

@Override
public List<PostDto> getPostsByExactTitleJPQL(String title) {
    return postRepository.getPostsByExactTitleJPQL(title)
            .stream()
            .map(this::mapToDTO)
            .collect(Collectors.toList());
}
```

### Controller Layer - PostController.java
```java
@GetMapping("/jpql-title")
public List<PostDto> getPostsByExactTitleJPQL(@RequestParam(name = "title") String title) {
    return postService.getPostsByExactTitleJPQL(title);
}

@GetMapping("/sql-description")
public List<PostDto> getPostsByDescriptionKeywordSQL(@RequestParam(name = "keyword") String keyword) {
    return postService.getPostsByDescriptionKeywordSQL(keyword);
}
```

## 5. Technology Comparison

| Technology          | Layer               | Description                                                                                                                                                                    |
|---------------------|---------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **Spring Data JPA** | High-level API      | A Spring abstraction over JPA that lets you define repository interfaces and automatically generate SQL queries using method names (e.g., `findByTitle`). Reduces boilerplate. |
| **Hibernate**       | JPA Provider        | A popular ORM framework that implements JPA. It maps Java objects to database tables and handles entity states, relationships, and SQL generation.                             |
| **HikariCP**        | Infrastructure      | A high-performance JDBC connection pool manager. Manages and reuses database connections efficiently. Default in Spring Boot.                                                  |
| **JDBC**            | Low-level API       | The core Java API for interacting with relational databases. Developers use it to execute SQL statements, manage connections, and process results — manually.                  |


## 6. JPA Relationships

### @OneToMany
Defines a one-to-many relationship. 
- A single entity (e.g., Post) can be related to multiple instances of another entity (e.g., Comment).
```java
@OneToMany(mappedBy = "post", cascade = CascadeType.ALL, fetch = FetchType.LAZY)
private Set<Comment> comments = new HashSet<>();
```

**mappedBy**: The field in the child entity (Comment) that owns the relationship.
- "there will be a post_id in comment table means that this comment belongs to which post"

**cascade**: Determines operations that should cascade to child entities.
  - CascadeType.ALL → propagate all operations (persist, remove, merge, etc.)
  - "when I change post → comments will be changed in the same operations as well"

**fetch**: Specifies when related data should be loaded.
  - FetchType.LAZY (default) → load only when accessed
  - FetchType.EAGER → load immediately

### @ManyToOne
Defines a many-to-one relationship. 
- Many entities (e.g., Comment) can relate to a single parent (e.g., Post).

```java
@ManyToOne(fetch = FetchType.LAZY)
@JoinColumn(name = "post_id", nullable = false)
private Post post;
```

**@JoinColumn**: Defines the foreign key column in the database.
- name = "post_id": the FK column
- lable = false: cannot be null

**fetch**: LAZY is usually preferred for performance.

### @ManyToMany
Defines a many-to-many relationship. A typical example is users and roles.
```java
@Entity
public class User {

    @Id
    private Long id;

    private String name;

    @ManyToMany(fetch = FetchType.LAZY)
    @JoinTable(
            name = "user_roles",
            joinColumns = @JoinColumn(name = "user_id"),              
            inverseJoinColumns = @JoinColumn(name = "role_id")       
    )
    private Set<Role> roles = new HashSet<>();  
}
```
**@JoinTable**: Defines the join (intermediate) table.
- joinColumns: FK to the current entity (user_id)
- inverseJoinColumns: FK to the other entity (role_id)

**fetch**: Choose LAZY to avoid fetching all related entities unless needed.

#### mappedBy
- Only used on the inverse side of a bidirectional relationship.
- Indicates the field name that owns the relationship.
- Avoids creating an additional join table.
  
#### cascade (CascadeType)
- Controls what operations should cascade to related entities.

#### fetch (FetchType)
- Determines when associated entities are loaded.
- EAGER (default for `@ManyToOne / @OneToOne`) -> Load related entities immediately
- LAZY (default for `@OneToMany / @ManyToMany`) -> Load only when accessed — improves performance

## 7. Cascade Options in JPA

### cascade = CascadeType.ALL
**Meaning**: This enables all cascading behaviors — it is equivalent to applying all of the following:
- PERSIST, MERGE, REMOVE, REFRESH, DETACH.

> When saving a Post entity, any associated Comment entities will also be saved automatically.
```java
@OneToMany(mappedBy = "post", cascade = CascadeType.ALL)
private List<Comment> comments;
```

### orphanRemoval = true
**Meaning**: If a child entity is removed from its parent’s collection, it is also deleted from the database.
> **Common use case**: In `@OneToMany` relationships, when remove a child from the list/set, comment becomes an “orphan” and will be deleted.
```java
post.getComments().remove(comment); // this comment will be deleted from DB too
```

### CascadeType
| CascadeType | Description                                                             | Use Case Example                                           |
|-------------|-------------------------------------------------------------------------|------------------------------------------------------------|
| PERSIST     | Owning entity saved ⇒ related entity saved                              | Save `Post`, automatically save associated `Comment`       |
| MERGE       | Owning entity merged ⇒ related entity merged                            | Update `Post`, automatically update associated `Comment`   |
| REFRESH     | Owning entity refreshed ⇒ related entity refreshed                      | Refresh `Post`, automatically refresh associated `Comment` |
| REMOVE      | Owning entity removed ⇒ related entity removed                          | Delete `Post`, automatically delete associated `Comment`   |
| DETACH      | Owning entity manually detached ⇒ related entity detached               | Detach `Post`, automatically detach associated `Comment`   |
| ALL         | All cascade operations on owning entity applied to related entity       | Perform all above operations automatically on `Comment`    |

## 8. Fetch Types in JPA

### 💤 FetchType.LAZY (Lazy Loading)
- **Meaning**: Related entities are not loaded immediately. They are fetched only when accessed.
- **Default for**: `@OneToMany`, `@ManyToMany` _X -> Many_
- **Use Case**:
  - When the related data is large or not always needed
  - Helps improve performance and reduce memory usage
> comments are not queried until you explicitly call post.getComments().
```java
@OneToMany(fetch = FetchType.LAZY)
private List<Comment> comments;
```

### ⚡️ FetchType.EAGER (Eager Loading)
- **Meaning**: Related entities are loaded immediately with the parent entity.
- **Default for**: `@ManyToOne`, `@OneToOne`  _X -> One_
- **Use Case**:
  - When related data is small or always required with the parent
  - Reduces the need for additional queries

> post will be loaded as soon as the Comment is fetched.
```java
@ManyToOne(fetch = FetchType.EAGER)
private Post post;
```
LAZY -> Child data is large, optional, or rarely accessed

EAGER -> Child data is small, required immediately, or critical to parent logic

# Querying and Data Access
## 9. JPQL Overview
> JPQL stands for Java Persistence Query Language.
It is a query language similar to SQL, but operates on Java entity objects (like Post, User), not database tables.

### 🔍 JPQL vs. SQL: Key Differences
| Feature             | JPQL                           | SQL                             |
|---------------------|--------------------------------|---------------------------------|
| Operates on         | Java entity classes & fields   | Database tables & columns       |
| Object-oriented     | ✅ Yes                          | ❌ No                            |
| Returns             | Entity objects                 | Raw data (rows, columns)        |
| Used in             | JPA / Hibernate                | JDBC / raw database access      |
| Portable across DBs | ✅ Yes                          | ❌ Depends on DB dialect         |

### 🌰 Example - Select
#### JPQL Example: Select Post by title = 'Spring Boot'
```java
@Query("select p from Post p where p.title = 'Spring Boot'")
List<Post> findPostWithSpringBootTitle();
```

#### Equivalent SQL:
```sql
SELECT * FROM posts WHERE title = 'Spring Boot';
```

### 🌰 Example - Join
#### JPQL Example: c.post is a mapped relationship (e.g. @ManyToOne)
```java
@Query("select c from Comment c join c.post p where p.id = :postId")
List<Comment> findCommentsByPostId(@Param("postId") Long postId);
```
- `Comment c` -> from the Comment entity
- `join c.post p` -> join the Post entity via the post field in Comment
- `p.id = :postId` -> filter by a specific post ID

#### Equivalent SQL:
```sql
SELECT c.* FROM comment c JOIN post p ON c.post_id = p.id WHERE p.id = ?
```
